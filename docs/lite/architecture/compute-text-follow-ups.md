# Compute text: deferred work

This is the durable follow-up backlog for scope deliberately left out of the
first Milestone 4 increment. The current delivery targets Devanagari shaping
and rendering with the pinned font, plus the shared-core and Arabic
correctness fixes. It does not complete Milestone 4.

These entries are deferred, not implemented, scheduled, or automatically
approved for implementation. Keep the identifiers stable. When a restriction
is added or deliberately retained, update this list with its reason and a
concrete revisit condition. When addressed, retain the entry and link its
implementation and validation.

## First-increment Arabic font policy

The user approved starting with Arabic fonts that provide OpenType joining
features. A font requiring unsupported fallback receives an explicit
unsupported-font error from the GPU path, rather than a claim of correctly
joined output.

This is an implementation support boundary, not a statement that the font is
invalid. HarfBuzz can synthesize joining substitutions from Unicode Arabic
Presentation Forms when the font maps those glyphs. That fallback is the first
follow-up below. Existing unmapped-character errors retain their precedence.

## Work that is not deferred

This backlog does not waive the current delivery's reference migration,
regression fixes, native GPU and lifecycle checks, authorized browser/rendered
witnesses, type/build checks, or bundle ceilings. Performance validation
remains a required gate before making performance claims; it is not converted
into an optional future task. Golden and ceiling changes remain separately
authorized operations.

HarfBuzz as a runtime dependency, reproducing reference-library bugs, and
creating separate engines by reference identity are not planned follow-ups.
